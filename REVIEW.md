# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-38) | Mixes naive UTC punch-in with IST shift start without timezone conversion; misses the strictly > 10:00 grace rule (R2); negative for early punches; ignores instant whole-second truncation (R1). | Punch-in at 09:40:01 IST returned 0 or 330 minutes depending on server timezone; early punch-in gave negative numbers. | Truncated instant to whole seconds, converted to UTC, compared against scheduled IST shift start in UTC, applied strictly > 600s check, and returned floor minutes since shift start. |
| 2 | `compute_work_hours` (lines 40-42) | Uses Python's standard `round()`, which performs banker's rounding (round half to even) rather than rule R4's required Half-Up rounding. | Duration yielding 8.125 hours rounded to 8.12 instead of 8.13. | Replaced with `Decimal(diff_seconds) / Decimal(3600)` quantized to 2 decimals using `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44-48) | Counts overtime for < 30 minutes (violating R3 $\ge 30$ min threshold); fails on overnight shifts where `shift_end` falls on the next calendar day. | Punch-out 15 minutes after shift end returned 15 instead of 0; overnight shift end evaluated on the wrong calendar day. | Adjusted scheduled shift end by +1 day when `shift_end <= shift_start`, computed floor minutes, and returned value only if $\ge 30$, otherwise 0. |
| 4 | `create_employee` (lines 77-86) | Check-then-insert race condition on `emp_code`; server-time timezone unawareness; `_id` handling. | Two concurrent POST requests with identical `emp_code` both returned 201; MongoDB allowed duplicates. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError` to return 409. |
| 5 | `create_employee` (lines 77-86) | Missing validation for `shift_start == shift_end` (contract forbids equal shift times); missing field format validations. | POST request with `shift_start: "09:30"` and `shift_end: "09:30"` succeeded with 201 instead of 422. | Added validation raising 422 Unprocessable Entity when `shift_start == shift_end` and validated input formats. |
| 6 | `list_employees` (lines 88-97) | Off-by-one pagination bug (`skip = page * page_size`); page 1 skipped the first 20 records. | `GET /employees?page=1` skipped the first 20 employees. | Corrected skip calculation to `(page - 1) * page_size`. |
| 7 | `list_employees` (lines 88-97) | `total = db.employees.count_documents({})` counted the entire collection instead of the filtered query (violates R10). | Filter `?department=Engineering` reported `total` as total company headcount instead of filtered count. | Passed filter query `q` to `count_documents(q)`. |
| 8 | `list_employees` (lines 88-97) | Missing mandatory sort stage; contract requires sorting by `emp_code` ascending. | Returned employees in non-deterministic MongoDB natural storage order. | Added `.sort("emp_code", ASCENDING)` to query. |
| 9 | `punch_in` (lines 99-122) | Check-then-insert race condition on `(emp_code, date)`. | Concurrent punch-ins for the same employee and date both succeeded with 201. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return 409. |
| 10 | `punch_in` (lines 99-122) | Crashes with 500 when `emp_code` does not exist (`emp["shift_start"]` on `None`). | POST `/attendance/punch-in` for unknown employee returned 500 instead of 404. | Added existence check returning 404 when employee does not exist. |
| 11 | `punch_in` (lines 99-122) | Naive datetime conversion via `fromtimestamp` ignores IST timezone, truncation, and overnight shifts (R1). | Early morning UTC punches assigned to wrong date; overnight punches before shift end assigned to wrong day. | Used UTC-aware instants, truncated to whole seconds, applied IST conversion and overnight shift previous-day logic. |
| 12 | `list_attendance` (lines 124-152) | In-memory loading and sorting (`docs = list(db.attendance_logs.find(q))`); violates scalability requirement on 100k docs. | High latency, memory spike, and timeout on 100,000 documents. | Applied database-level `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 13 | `list_attendance` & `punch_in` | Leaked `id = str(doc.pop("_id"))` into response; OpenAPI specifies `_id` is internal and must never appear. | Client received uncontracted `id` field. | Converted documents strictly to `AttendanceRecord` schema without `_id` or `id`. |
| 14 | `health` (lines 72-75) | Readiness probe returned `{"status": "ok"}` without checking MongoDB connection. | Returned 200 when database was disconnected or down. | Pinged MongoDB with `db.command("ping")` and returned 503 when unreachable. |

### Examined and Decided NOT a Defect:
- **`sample_seed.py` dropping existing data:** This is intended for initial local test data seeding and resetting sample data; the main application lifespan correctly uses idempotent index creation (`create_index`) and does not drop any collections or data at startup.
- **`dotenv.load_dotenv()` at startup:** Reading environment variables from `.env` while giving priority to real environment variables matches the configuration requirement.
